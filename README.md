# Jara Finance

An AI-powered personal finance coach for Ghana. Track income and expenses across cash, Mobile Money and bank accounts, build monthly budgets, hit savings goals, and ask Salo what you can actually afford.

> **Know where your money goes, what you can afford, and what to do next.**

**Jara** is the app — shortened from Jara Finance everywhere in the interface.
**Salo** is the AI coach inside it: the `/assistant` screen, the system prompt
and everything under `server/ai/`. The two names are not interchangeable.

## Requirements

- **Node 22.22.0** — pinned in `.nvmrc`. Run `nvm use`. Nuxt 4.6 does not support Node 20.
- **pnpm 10**
- **Docker** — for local Postgres.

## Getting started

```bash
nvm use
pnpm install
cp .env.example .env     # then fill in BETTER_AUTH_SECRET and an AI key
pnpm db:up               # start Postgres on :5432
pnpm db:migrate          # apply migrations
pnpm db:seed             # system categories
pnpm dev                 # http://localhost:3100
```

Port **3100**, not 3000 — 3000 is taken by another local app.

Generate an auth secret with `openssl rand -base64 32`.

## Architecture

A modular monolith. Nuxt handles both the UI and the API; there is no separate backend service.

```
app/
  pages/        Routes; afford.vue is the primary screen
  components/   Jara's own components; ui/ is generated by shadcn-vue
  composables/  useCurrentUser (auth state from /api/me), useColourMode (theme)
  middleware/   auth.global.ts — the route gate
  layouts/      default (app shell) and auth (signed-out pages)
  assets/css/   main.css — the design tokens, and the only place colour is defined
server/
  api/          HTTP endpoints
  services/     Domain logic — the only place financial maths happens
  ai/           Swappable provider, system prompt, and tools/
  ai/tools/     Read-only tools the AI coach may call
  database/     Drizzle schema + migrations
  utils/        auth, session guards, db, request validation
shared/         Used by both sides: money, periods, Zod schemas
tests/          unit/ + integration/ (Vitest) and e2e/ (Playwright)
```

### The affordability screen

`/afford` is the screen the product is built around. It answers "can I afford
GH₵X?" from

```
available = liquid − committedSavings − remainingBudgetedSpend
verdict   = compare(price, available)     // yes · tight · no
```

and draws that subtraction as a field of equal cells — struck for money promised
to a goal, hatched for money budgeted but not yet spent, open for what is
actually yours. It opens on the breakdown and asks for a price second, so the
verdict is always read against figures already on screen.

`/api/affordability` takes an **optional** `price`. Without one it returns the
half of the formula that needs no price, which is what the screen and the
dashboard's headroom strip both read. The AI coach's `checkAffordability` tool
calls the same service, so the figure on screen and the figure Salo quotes
cannot diverge.

### Design

The visual world is the susu collector's tally card: pale ruled stock, a deep
susu-green shell carrying navigation, and stamp ink for money already promised.
Tokens live in `app/assets/css/main.css` and are defined twice, for light and
dark; `DESIGN.md` records the system. Typography is Archivo, self-hosted by
`@nuxt/fonts` — no request leaves the page for a font.

`app/components/ui/` is vendored shadcn-vue and is regenerated by the CLI, so it
is never hand-edited. The few places its defaults conflict with the design (box
shadows, the badge's pill radius) are overridden by un-layered rules at the
bottom of `main.css`, which beat utility classes without `!important`.

### Rules that are not negotiable

1. **Money is integer pesewas.** Never a float, anywhere in the money path. Use `shared/money`.
2. **Balances come from `server/services/balances.ts`.** Nothing recomputes a balance inline.
3. **Every user-data query filters by `userId` in its `where` clause** — never by checking ownership in JS after fetching.
4. **The AI never does arithmetic.** It calls a tool, gets numbers, and explains them. If a figure isn't in a tool result, Salo doesn't state it.
5. **Transfers are two rows sharing a `transferGroupId`**, written in one transaction. They are never income or expense.

### Tests

`pnpm test` runs two suites; `pnpm test:e2e` runs a third.

- **`tests/unit/`** — pure domain logic in plain Node: money arithmetic, calendar
  maths, the balance formula. No database, no Nuxt runtime, millisecond runtime.
- **`tests/integration/`** — the real SQL against a real Postgres: filtered
  aggregates, cross-tenant isolation, and every CHECK and UNIQUE constraint. These
  **skip themselves** when `DATABASE_URL` is unset, so the suite still passes on a
  machine with no database. Run `pnpm db:up && pnpm db:migrate && pnpm db:seed`
  first to actually exercise them.
- **`tests/e2e/`** — Playwright, against a real browser: the auth gate, and a new
  user signing up, adding an account, recording money and setting a budget.
  Reuses a dev server if one is already running on :3100, otherwise starts one.
  Run `pnpm exec playwright install chromium` once first.

The split matters because the three fail differently. A unit test cannot catch an
aggregate that counts transfers as income; an integration test cannot run fast
enough to cover every rounding edge case; neither notices that a form silently
does nothing in a browser.

Anything that touches a form in an e2e test must navigate via the spec's
`gotoReady` helper, which waits for hydration. Filling a field before Vue
hydrates leaves the value in the DOM and the component state empty, so the form
looks filled and submits nothing.

### AI provider

Swappable via `AI_PROVIDER` in `.env`: `openrouter` (default), `anthropic` or
`openai`. All three resolve to the same `LanguageModel` in
`server/ai/provider.ts`, so nothing else in the app knows which is in use.

**OpenRouter is the default** because one key reaches every model worth using
here. Salo's model is close to a commodity in this design — it picks a tool and
explains what came back, it never reasons about money — so being able to change
model with an env var, without opening a new vendor account, is worth more than
a direct connection to any one provider.

Get a key at [openrouter.ai/keys](https://openrouter.ai/keys) and set
`OPENROUTER_API_KEY`. Note that a ChatGPT Plus or Claude.ai subscription does
**not** include API access — consumer subscriptions and metered API keys are
separate products.

`AI_MODEL` overrides the model. The OpenRouter default is
`~anthropic/claude-sonnet-latest`, a *latest alias* that tracks the current
model in that family; pinned slugs are retired as new versions ship, so
hardcoding one is a deployment that breaks on someone else's release schedule.
Whatever you choose **must support tool calling** — filter for it at
[openrouter.ai/models?supported_parameters=tools](https://openrouter.ai/models?supported_parameters=tools).
A model without tools cannot answer anything, because Salo is forbidden from
stating a figure no tool gave it.
